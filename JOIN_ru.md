# Вас пригласили в репозиторий команды — что делать

Репозиторий команды — общая папка на GitHub, где лежит всё, что команда делает на
программе. Работать с ним вы будете через свою ИИ-модель: она сама выполняет
команды, а вы говорите, что нужно сделать. Знать GitHub не нужно.

Ниже `<адрес>` — адрес репозитория команды в виде `владелец/название` (его пришлёт
владелец репозитория).

## Шаг 1. Примите приглашение

1. Найдите письмо от GitHub «… invited you to collaborate on …» и нажмите
   **View invitation** → **Accept invitation**. Письма нет — откройте
   https://github.com/notifications.
2. Нет аккаунта на GitHub — зарегистрируйтесь на https://github.com/signup на ту
   же почту, на которую пришло приглашение, и сообщите владельцу свой логин.
3. Включите двухфакторную защиту: GitHub → Settings → Password and
   authentication. Резервные коды сохраните не в телефоне.

## Шаг 2. Подготовьте модель

Нужна модель, которая умеет выполнять команды на вашем компьютере: **Claude
Code**, **Codex CLI** или **Cursor**. Веб-чат в браузере не подойдёт.

1. Создайте папку для работы, например `program-workspace` в домашней папке.
2. Откройте в ней терминал (macOS — «Терминал», Windows — PowerShell) и
   запустите модель.

## Шаг 3. Скопируйте модели этот текст

```text
Прочитай https://github.com/viberesearch/triad-workspace-template/blob/main/rules/setup_join.yaml и подключи меня к репозиторию команды <адрес>. Я не знаю GitHub: объясняй каждый шаг простыми словами и спрашивай меня, когда нужно моё решение или действие.
```

Модель проверит и при необходимости установит нужные программы, скачает
репозиторий команды и хаб программы и коротко расскажет, что в них лежит.

**Одно действие — ваше: вход в GitHub.** Когда модель попросит, откройте
**второе окно терминала** и выполните:

```text
gh auth login --web --git-protocol https
```

Скопируйте показанный код, нажмите Enter, в открывшемся браузере вставьте код и
подтвердите. Вернитесь к модели и скажите «готово».

## Шаг 4. Одобрите первый pull request

Pull request (PR) — предложение участника что-то изменить. Изменение попадает в
общий репозиторий, только когда его посмотрел и одобрил другой участник. Скорее
всего, вас уже ждёт PR, где вас добавили в состав команды.

**Через модель:**

1. Скажите: «Покажи открытые PR и перескажи, что в них».
2. Прочитайте пересказ. Модель отдельно покажет, удаляется ли что-нибудь.
3. Всё верно — скажите: «Одобри PR №<номер>». Нужны правки — «Попроси в PR
   №<номер> исправить: <что именно>».

**Через сайт:** откройте ссылку на PR → вкладка **Files changed** → кнопка
**Review changes** → **Approve** → **Submit review**.

Сливает PR в общий репозиторий обычно его автор, после вашего одобрения.

## Шаг 5. Обычная работа

Запускайте модель в папке репозитория команды и пишите:

```text
Работай по AGENTS.md. Задача: <что нужно сделать>.
```

| Нужно | Скажите модели |
|---|---|
| Посмотреть правки коллег | «Покажи открытые PR и перескажи, что в них» |
| Узнать, что нового в хабе программы | «Что нового в хабе?» |
| Сдать материалы организаторам | «Подготовь сдачу в хаб по rules/program_hub.yaml» |
| Что-то удалилось или сломалось | «Что-то пошло не так: <что>. Разберись по rules/recover.yaml» |
| Обновить правила | «Обнови правила из шаблона» |

## Три правила

1. Всё, что лежит в репозитории, видят все участники команды и провайдеры их
   моделей. Ключи, пароли и данные клиентов туда не кладутся.
2. Любую ошибку можно откатить: история хранит всё. Если сомневаетесь — спросите
   модель, прежде чем удалять.
3. Подробнее — в `PROTOCOL.md` (правила для людей) и `HOW_IT_WORKS.md` (схемы).
