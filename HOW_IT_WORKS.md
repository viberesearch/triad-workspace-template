# Как это работает — схемы для тех, кто не работал с GitHub

## 1. Пять слов, которые нужно знать

| Слово | Что это простыми словами |
|---|---|
| **Репозиторий** | Папка с файлами, которая помнит каждое изменение: кто, когда и что поменял |
| **Клон** | Копия репозитория на вашем компьютере. Вы работаете в ней, а не на сайте |
| **Коммит** | Сохранённый шаг: «вот что я изменил и почему». Любой шаг можно вернуть |
| **Ветка** | Черновая линия работы. Основная линия называется `main`; свою правку вы делаете в ветке, чтобы не мешать остальным |
| **Pull request (PR)** | Просьба «добавьте мою ветку в main». Другой участник смотрит изменения и одобряет |

Всё это за вас делает модель. Вам достаточно сказать, что нужно сделать, и
отвечать на её вопросы.

## 2. Кто где работает

```mermaid
flowchart TB
    subgraph PUB["Публично на GitHub"]
        TA["Шаблон команды<br/>triad-workspace-template"]
        TD["Шаблон хаба<br/>cohort-hub-template"]
    end
    subgraph ORG["Организаторы (приватно)"]
        HUB["Хаб программы<br/>записи, транскрипты, материалы"]
    end
    subgraph TEAM1["Команда 1 (приватно)"]
        R1["Репозиторий команды 1"]
    end
    subgraph TEAM2["Команда 2 (приватно)"]
        R2["Репозиторий команды 2"]
    end
    TD -- "организаторы создают хаб из шаблона" --> HUB
    TA -- "каждая команда создаёт свой репозиторий" --> R1
    TA --> R2
    HUB -- "все участники читают" --> R1
    HUB -- "все участники читают" --> R2
    R1 -. "сдача материалов через issue" .-> HUB
    R2 -. "сдача материалов через issue" .-> HUB
```

- Шаблоны публичные и пустые: в них только структура и правила.
- Хаб видят все участники программы; менять его могут только организаторы.
- Репозиторий команды видит только команда. Другие команды его не видят.

## 3. Что лежит у вас на компьютере

```mermaid
flowchart LR
    subgraph GH["GitHub (облако)"]
        RT["Репозиторий команды"]
        HB["Хаб программы"]
    end
    subgraph PC["Ваш компьютер: папка program-workspace"]
        CT["клон репозитория команды<br/>здесь вы работаете"]
        CH["клон хаба<br/>только читать"]
        M["Ваша модель<br/>Claude Code, Codex, Cursor…"]
    end
    RT -- "pull: забрать новое" --> CT
    CT -- "push: отправить своё" --> RT
    HB -- "pull: забрать новое" --> CH
    M --> CT
    M --> CH
```

У каждого участника своя модель. Все модели читают одни и те же правила в
папке `rules/`, поэтому делают одно и то же одинаково.

## 4. Обычный день

```mermaid
sequenceDiagram
    actor Вы
    participant М as Ваша модель
    participant Р as Репозиторий команды
    actor К as Коллега
    Вы->>М: «Работай по AGENTS.md. Задача: обнови карту после модуля»
    М->>Р: забрать новое (pull), открыть ветку
    М->>М: правка, проверка scripts/check.sh
    М->>Вы: вот что изменено, вот что удалено — отправлять?
    Вы->>М: да
    М->>Р: коммит, push, pull request
    М->>Вы: попросите коллегу посмотреть PR
    К->>Р: смотрит изменения (через свою модель) и одобряет
    М->>Р: слить в main
```

## 5. Атомы и то, что из них строится

```mermaid
flowchart LR
    subgraph ATOMS["Атомы: хранятся как есть, не меняются"]
        T["Транскрипты лекций<br/>и разборов"]
        MAT["Материалы"]
        S["Сдачи команд"]
    end
    subgraph DER["Производное: всегда можно пересобрать"]
        SUM["Конспекты"]
        PL["Итоги разборов"]
        CAT["Указатели по темам"]
        TD["Карта и ставка команды"]
    end
    T --> SUM
    T --> PL
    T --> CAT
    MAT --> SUM
    S --> PL
    T --> TD
    MAT --> TD
```

Любой вывод ссылается на атом — вплоть до минуты записи. Если вывод оказался
неверным, его пересобирают из атомов; сами атомы не трогают.

## 6. Как запись с модуля становится материалом команды

```mermaid
flowchart LR
    A["Занятие модуля"] --> B["Аудиозапись"]
    B --> C["Распознавание речи<br/>и разметка спикеров"]
    C --> D["Черновик транскрипта<br/>в хабе — атом"]
    D --> E{"Окно проверки:<br/>участник просит<br/>убрать фрагмент?"}
    E -- "да" --> F["Организаторы<br/>изымают фрагмент"]
    E -- "нет" --> G["Транскрипт опубликован<br/>в хабе, дословно"]
    F --> G
    G --> H["Команды забирают<br/>(pull)"]
    H --> I["Ссылки и цитаты<br/>в карте, ставке, выводах"]
```

Сказать «это не для записи» можно до начала разговора. Если лишнее всё же
попало в транскрипт — в окно проверки можно попросить его убрать.

## 7. Как меняются правила

```mermaid
flowchart TB
    TA["Шаблон команды: rules/"] -- "«обнови правила» → PR" --> RT["rules/ в репозитории команды"]
    LOC["rules/local/ — правила вашей команды"] --> RT
    HUBR["Хаб: rules/for_teams.yaml — правила организаторов"] -- "читается при каждом pull" --> M["Модель участника"]
    RT --> M
```

- Общие правила обновляются из шаблона по команде «обнови правила».
- Правила вашей команды лежат в `rules/local/`; обновления их не трогают.
- Правила организаторов (сроки, форматы) лежат в хабе и действуют сразу после
  `pull`.

## 8. Если что-то сломалось

```mermaid
flowchart LR
    X["Что-то удалено или испорчено"] --> Y["Скажите модели:<br/>«что-то пошло не так, разберись по rules/recover.yaml»"]
    Y --> Z["Модель находит прежнее состояние<br/>в истории и возвращает его через PR"]
```

Всё, что было закоммичено, хранится в истории, и у каждого участника есть
полная копия. Вернуть можно почти всё. Исключение одно: ключ, пароль или чужие
данные, попавшие в репозиторий, считаются раскрытыми. Ключ сразу меняют, а о
данных сообщают владельцу репозитория.
