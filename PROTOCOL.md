# Протокол командного репозитория — для людей

Подробные правила для моделей — в `rules/`. Здесь — то, что нужно знать людям.

## Пять принципов
1. **Всё, что лежит в репозитории, видят все участники и провайдеры их моделей.**
   Кладём только то, что готовы отдать всем в команде.
2. **В main — через pull request.** Нужно ли одобрение другого участника, команда
   решает сама (`approval` в `rules/local/team.yaml`; по умолчанию — нужно).
3. **Ошибки исправляются новым шагом**, а не переписыванием истории. Прежние
   версии документов — в `archive/`.
4. **У каждого живого документа есть владелец** (`INDEX.md`). Остальные
   предлагают правки, решает владелец.
5. **Факт без источника — гипотеза.**

## Роли
- **Владелец репозитория** создаёт его, приглашает и удаляет участников.
  Преемник на случай выхода владельца записан в `team/README.md`.
- **Участники** работают на равных. На GitHub у них право записи (у личного
  аккаунта других ролей нет).
- Всем — двухфакторная аутентификация на GitHub; резервные коды хранятся вне
  телефона.
- Каждый выбирает свою модель и отключает у провайдера обучение на своих данных,
  где это возможно.

## Что сказать модели
| Нужно | Скажите |
|---|---|
| Создать репозиторий команды | промпт из `README.md` («Прочитай … setup_create.md …») |
| Подключиться | промпт из `README.md` («Прочитай … setup_join.md …») |
| Любая работа | «Работай по AGENTS.md. Задача: …» |
| Посмотреть правки коллеги | «Покажи открытые PR и перескажи, что в них» |
| Что-то сломалось | «Что-то пошло не так: <что>. Разберись по rules/recover.yaml» |
| Обновить правила | «Обнови правила из шаблона» |
| Сдать материалы организаторам | «Подготовь сдачу в хаб по rules/program_hub.yaml» |

## Нештатные ситуации
| Ситуация | Что делать |
|---|---|
| Удалили или испортили файл | модель вернёт его из истории (`rules/recover.yaml`) |
| Ошибка попала в main | откат через новый PR (кнопка «Revert» или `git revert`) |
| Модель переписала слишком много | PR не сливать; начать заново с задачей поменьше |
| Удалили ветку или репозиторий | ветку — кнопкой «Restore branch»; репозиторий владелец восстанавливает 90 дней; иначе — из клона любого участника |
| Переписали историю main | владелец восстанавливает main из полного клона |
| Закоммитили ключ или пароль | **сразу сменить ключ у выдавшего сервиса**, потом чистить |
| Закоммитили закрытое | считать раскрытым; владелец вычищает историю; все клонируют заново |
| Участник уходит | владелец снимает доступ; копия у ушедшего остаётся; его документы получают нового владельца |
| Разногласие по документу | решает владелец документа, несогласие — в `journal.md`; тема команды — консенсусом |
| GitHub недоступен | работаем локально, отправляем позже |
